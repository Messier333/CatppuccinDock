## 리버스 프록시 API에서 링크 가져오기

**관리자 → API 링크 가져오기 → 원하는 앱 카드 → 연결 등록**에서 관리 서비스 기본 주소와 API 토큰을 등록하세요. 예를 들어 NPM의 기본 주소는 `http://192.168.1.10:81`처럼 관리 API가 있는 주소입니다. `/api`를 포함한 조회 경로는 서비스 종류에 맞춰 붙입니다. 서버에서 접근할 수 있는 내부 주소도 사용할 수 있습니다.

| 서비스 | 읽기 API | 인증 |
| --- | --- | --- |
| Nginx Proxy Manager | `GET /api/nginx/proxy-hosts` | Bearer 액세스 토큰 (만료 시 교체) |
| Nginx Proxy Guard | `GET /api/v1/proxy-hosts?page=1&per_page=100` | `ng_` API 토큰, 호스트 조회 권한 |
| Zoraxy | `GET /plugin/api/proxy/list?type=host` | `/api/proxy/list` 권한을 허용한 Plugin API 키 |

공식 API 기준: [NPM 스키마](https://github.com/NginxProxyManager/nginx-proxy-manager/blob/develop/backend/schema/paths/nginx/proxy-hosts/get.json), [Nginx Proxy Guard API](https://nginxproxyguard.com/en/docs/api), [Zoraxy Plugin API](https://github.com/tobychui/zoraxy/blob/main/src/plugin_api.go). 설치된 버전이 이 API를 제공해야 합니다.

**링크 미리 보기**로 도메인을 조회한 뒤 선택하고 본인의 카테고리로 가져옵니다. API 조회와 가져오기는 관리자만 사용할 수 있으며, 일반 사용자는 본인 북마크 편집과 계정 보안을 관리합니다. 비활성 호스트·스트림 프록시·와일드카드·중복 도메인은 제외합니다. 미리 보기는 사용자에게 귀속되며 10분 후 만료되고 한 번 가져온 뒤에는 다시 조회해야 합니다. 본인에게 이미 있는 동일 URL은 중복 추가하지 않습니다. 최대 호스트/링크 수는 1,000개입니다.

NPM·NPG는 호스트 인증서 설정으로 HTTP/HTTPS를 추정하거나 직접 지정할 수 있습니다. Zoraxy는 목록 API가 전역 TLS 사용 여부를 포함하지 않아 HTTP/HTTPS를 직접 선택합니다. TLS 우회 호스트는 HTTP로 가져옵니다. 외부 접속 포트도 지정할 수 있습니다. 가져온 이름·URL·아이콘은 내 북마크에서 수정하세요. 예약 동기화는 수행하지 않고 요청할 때 읽어 복사합니다.

토큰은 DB에 암호화하여 저장하고 반환하지 않습니다. TLS 인증서 검증은 기본 활성화이며, 자동 리다이렉트를 따라가지 않습니다. 연결 실패·토큰 만료·권한 부족은 미리 보기 단계에서 표시합니다. 등록 주소나 서비스 종류를 바꾸면 다른 서버로 기존 토큰이 전송되지 않도록 토큰을 다시 입력해야 합니다.

## 다른 앱의 API 직접 등록

**API 링크 가져오기 → 서비스 등록**은 NPM/NPG/Zoraxy 이외 앱의 목록 API를 연결하는 기능입니다. 기본 지원 앱은 각 앱 카드의 **연결 등록**을 사용하세요.

다른 앱은 서비스 이름·기본 주소·GET API 경로·인증 방식(Bearer / API 키 헤더 / 인증 없음)을 입력하고 JSON 필드를 지정합니다. 예를 들어 응답이 `{"data":{"items":[{"title":"Photos","target":{"url":"https://photos.example.com"}}]}}`이면 목록 배열 경로는 `data.items`, URL 필드는 `target.url`, 이름 필드는 `title`입니다. 최상위 배열은 목록 경로를 비워 두고, 문자열 배열은 URL 필드도 비워 둡니다. URL 필드가 문자열 배열인 경우 별칭을 각각 링크로 만듭니다. 도메인 형식은 프로토콜과 외부 포트를 선택할 수 있고, 전체 URL 형식은 API의 경로·포트를 보존합니다.

API 호출은 관리자만 실행할 수 있습니다. 토큰은 암호화하여 DB에 저장하며 조회 응답에 포함하지 않습니다. 인증 헤더에는 `Authorization` 또는 `X-` 접두사 헤더를 사용할 수 있습니다. 인증 키를 기본 주소·API 경로·쿼리 문자열에 넣지 마세요. 다른 주소로 리다이렉트하지 않으며, 응답은 2MB·목록 1,000개로 제한합니다. 한 번의 GET으로 JSON 목록을 제공하는 API를 지원하고 별도 로그인 교환·GraphQL·페이지 순회는 전용 어댑터가 필요합니다. 미리 보기에서 내용을 확인한 뒤 선택한 항목만 가져옵니다.

## 하단바·외부 모니터링·화면 편집

관리자의 **하단바 · 모니터링**에서 하단바의 기본 순서와 항목별 표시 여부를 설정합니다. 설정·로그아웃은 항상 남습니다. 화면 순서 편집 버튼도 목록에서 위치·표시 여부를 설정할 수 있으며, ‘메인에서 순서 편집’으로 편집 화면에 바로 진입할 수 있습니다. 메인의 연필 버튼으로 개인 하단바 순서와 탭·카테고리·북마크 순서를 드래그하여 변경할 수 있습니다. 손잡이에 포커스를 두고 방향키로도 이동할 수 있으며 변경 즉시 DB에 저장됩니다. 하단바 기본 순서 복원은 개인 순서를 지우고 관리자 구성을 적용합니다.

외부 모니터링 위젯은 다음을 지원합니다. 위젯마다 숫자·작은 그래프 또는 Kuma 상태 도트를 선택할 수 있고 기본 공개 대상은 관리자입니다. 모든 사용자에게 공개하면 해당 수치가 로그인한 모든 사용자에게 표시됩니다.

| 서비스 | 등록 정보 | 동작 |
| --- | --- | --- |
| Prometheus | 기본 URL, PromQL, 필요한 경우 Bearer 토큰 | `/api/v1/query_range`로 하나의 시계열 조회 |
| Grafana | 기본 URL, Prometheus 데이터 소스 UID, PromQL, 조회 권한이 있는 서비스 계정 토큰 | 데이터 소스 프록시를 통해 Prometheus 조회 |
| Uptime Kuma | 기본 URL, 게시된 상태 페이지 Slug, 모니터 ID | 상태·응답 시간·24시간 가동률 조회 |

CPU 사용률 예: `100 * (1 - avg(rate(node_cpu_seconds_total{mode="idle"}[5m])))`. 메모리 사용률은 호스트가 여러 개라면 `avg(100 * (1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes))`처럼 집계하세요. 표시 단위는 수치 변환 없이 뒤에 붙습니다. PromQL은 반드시 한 시계열을 반환해야 합니다. 토큰은 서버 DB에 암호화되며 일반 사용자 응답에는 API 주소·쿼리·토큰이 포함되지 않습니다. 서비스 주소를 바꾸면 기존 토큰을 제거합니다. 내부 주소는 명시적으로 허용해야 하며 TLS 인증서 검증과 DNS 주소 검증을 적용하고 리다이렉트는 따르지 않습니다. 기본 조회 간격은 60초이며 인증 오류 이후 자동 재시도는 하루 동안 유예합니다.

날씨에 마우스를 올리면 테마에 맞는 상세 정보가 나타납니다. 새로고침 아이콘은 요청 중 회전하며 수동 조회는 최대 1분에 한 번 새 데이터를 요청합니다. 시계에 마우스를 올리거나 누르면 월·연도를 바꾸고 오늘로 돌아갈 수 있는 달력이 열립니다. 날짜와 시계는 설정한 시간대를 따릅니다.

연동 규격: [Prometheus HTTP API](https://prometheus.io/docs/prometheus/latest/querying/api/), [Grafana 데이터 소스 API](https://grafana.com/docs/grafana/latest/developer-resources/api-reference/http-api/api-legacy/data_source/), [Uptime Kuma 내부 API](https://github.com/louislam/uptime-kuma/wiki/Internal-API). Kuma 상태 페이지 API는 내부 API이므로 서비스 버전에 따라 변경될 수 있습니다.

설정 화면 왼쪽의 **순서 편집**을 누르면 메뉴 손잡이가 나타납니다. 드래그하거나 손잡이에서 위·아래 방향키를 누르면 계정별 메뉴 순서가 즉시 DB에 저장되며 재접속 후에도 유지됩니다. 편집 모드의 기본 순서 복원 버튼으로 되돌릴 수 있습니다. 사용자의 메뉴 순서와 역할에 따른 메뉴 접근 권한은 각각 유지됩니다. 시계 달력은 호버로 열면 영역을 벗어나는 즉시 닫히고, 클릭하면 고정되며 한 번 더 클릭하면 닫힙니다. 하단바 상세 패널은 한 번에 하나만 열립니다.

**서비스 상태 → 북마크 일괄 등록**에서 탭·카테고리·검색으로 목록을 좁혀 여러 북마크를 한 번에 선택할 수 있습니다. 같은 URL은 한 번만 등록하고 기존 대상은 건너뜁니다. 확인 간격과 내부 네트워크 허용 여부를 공통으로 지정하며 확인 URL은 각 북마크 URL로 시작합니다. 내부 상태 확인 주소를 따로 쓰려면 등록 후 개별 수정하세요. **전체 상태 확인**은 활성화된 모든 대상을 서버에서 확인하고 진행 상황을 표시합니다. 최근 15초 내 확인한 대상과 중지한 대상은 제외합니다. 정상 및 인증 필요 응답은 초록, 서비스 오류·연결 실패는 빨강입니다.

자동 상태 확인은 메인 화면의 **실제로 보이는 북마크**만 대상으로 합니다. 스크롤·탭 전환으로 새 북마크가 보이면 확인을 요청하고, 계속 보이는 북마크는 1분마다 갱신 여부를 확인합니다. 서버는 설정한 확인 간격 이내의 결과를 재사용하며 같은 대상의 동시 요청을 합쳐 최대 4개씩 처리합니다. 갱신 중에는 마지막으로 확인한 도트 색상을 유지합니다. 숨긴 브라우저 탭에서는 요청을 중지하고, 메인 화면을 보는 사람이 없으면 자동 상태 확인도 실행하지 않습니다. 대상은 최대 1,000개, 일괄 등록은 한 번에 최대 200개입니다. 관리자의 **전체 상태 확인**은 화면에 보이지 않는 대상도 확인합니다.

설정 화면 왼쪽의 **기능 검색**에서 메뉴 이름이나 `2FA`, `슬라이딩`, `Grafana` 등 관련 키워드로 기능을 찾을 수 있습니다. 검색에는 현재 계정이 접근할 수 있는 메뉴만 포함됩니다. 데스크톱에서는 왼쪽 메뉴의 오른쪽 경계를 드래그해 너비를 바꿀 수 있으며 계정별로 이 브라우저에 기억합니다. 경계를 두 번 클릭하면 기본 너비로 돌아갑니다. 키보드로 경계에 초점을 두고 좌우 방향키로 조절할 수도 있습니다.

탭 전환 애니메이션은 **개인 설정 · 앱 설치 → 내 슬라이드 효과**에서 `기기 설정 따르기 / 항상 켜기 / 끄기`로 지정합니다. 포털 설정의 중복 체크박스는 제거했습니다. 기능 검색에서 `슬라이딩`을 검색해도 이 개인 설정으로 이동합니다. 기존 개인 설정과 백업 호환성은 유지합니다.

## 개인 Proxmox 연동

**서비스 연동 → 내 Proxmox**에서 본인 API 토큰을 등록해 북마크 요약과 상세 패널을 구성할 수 있습니다. VM/LXC 전원·스냅샷·백업·복제·이동·자원 변경 등 20종 작업은 토큰의 유효 권한과 서버 상태에 따라 제공합니다. 연결은 등록한 계정만 사용할 수 있습니다. [Proxmox 설정·권한·지원 범위](proxmox.md)
