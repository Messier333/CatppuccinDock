# 내 Proxmox 연동

설정 화면의 **서비스 연동 → 내 Proxmox → Proxmox 추가**에서 연결합니다. 관리자와 일반 사용자 모두 본인 연결을 등록할 수 있습니다. 연결·API 주소·상태·작업 내역·레이아웃은 등록한 계정에 귀속됩니다. 다른 포털 관리자를 포함한 다른 계정의 API 접근도 404로 거절합니다. 공유 링크를 통해 같은 URL을 추가해도 연동은 공유되지 않습니다.

## 연결 준비

1. Proxmox의 **Datacenter → Permissions → Users**에서 전용 사용자를 준비합니다.
2. **API Tokens**에서 토큰을 만들고 Token ID (`dock@pve!portal` 형식)와 한 번만 표시되는 Secret을 준비합니다.
3. 필요한 노드·VM·스토리지 범위에 권한을 부여합니다. Privilege Separation을 사용하면 사용자와 토큰 **양쪽에** ACL이 있어야 합니다. 사용자와 토큰의 유효 권한 교집합을 사용합니다.
4. CatppuccinDock에서 HTTPS 주소 (`https://pve.example:8006`), Token ID, Secret을 입력합니다. 자체 CA를 사용하면 **사용자 CA 인증서**에 PEM을 입력하세요. 기본 Proxmox CA는 노드의 `/etc/pve/pve-root-ca.pem`입니다. 개인 키는 입력하지 않습니다. 접속 호스트가 서버 인증서의 이름과 일치해야 합니다.
5. 필요하면 노드 이름을 쉼표로 구분해 조회·제어 범위를 더 제한합니다. 비워 두면 토큰으로 조회할 수 있는 노드를 사용합니다. 사설 주소 연결 허용은 홈랩용 기본값이며 루프백·링크 로컬·메타데이터 주소는 허용하지 않습니다.
6. 내 북마크를 선택하고 **저장 · 연결 확인**을 누릅니다. 제어는 기본적으로 꺼져 있습니다. 실행할 작업의 Proxmox 권한을 부여한 뒤 **서버 제어 허용**을 켜세요.

TLS 인증서는 항상 검증합니다. Secret은 `AUTH_ENCRYPTION_KEY`로 암호화해 DB에 저장하고 API 응답에 반환하지 않습니다. 주소나 Token ID를 변경하면 Secret을 다시 입력해야 합니다. 이 키는 업데이트 시 유지하세요.

## 북마크 요약과 상세 패널

- 북마크 이름을 누르면 기존처럼 서비스 주소가 열립니다. 오른쪽 요약 버튼은 Proxmox 상세 패널을 엽니다.
- 요약에는 **가동 게스트 수·온라인 노드 수·CPU·메모리·스토리지** 중 최대 3개를 고릅니다. 모두 해제하면 상세 보기 아이콘을 표시합니다. 연결한 북마크들은 해당 연결의 요약 설정을 사용합니다.
- CPU는 온라인 노드의 코어 수에 따른 가중 평균, 메모리는 온라인 노드의 합계 사용률입니다. 스토리지는 API가 반환한 노드별 스토리지 사용량의 합계 비율입니다. 공유 스토리지가 여러 노드에 표시되면 중복 합산될 수 있습니다.
- 상세 패널에는 요약·노드·VM/LXC·스토리지·이 앱의 작업 내역이 있습니다. 게스트는 이름·ID·노드로 검색하고 종류·상태로 필터링합니다.
- 상세 패널의 연필 버튼에서 **실제 카드를 드래그**해 순서를 바꾸고, 표시 여부와 전체/절반 너비를 고릅니다. 손잡이에 포커스를 두고 위아래 방향키로도 이동할 수 있습니다. 북마크 요약 지표와 게스트 목록 열도 변경하고 **구성 저장**을 누릅니다. 설정 화면에서도 같은 구성을 편집할 수 있습니다.
- 메인 패널의 비율과 크기는 바뀌지 않습니다. 상세 패널은 별도로 열리며 모바일에서는 전체 너비를 사용합니다.

## 지원하는 제어

리소스를 누르면 현재 토큰의 유효 권한을 다시 조회해 가능한 작업만 메뉴에 표시합니다. 조회 전용 연결과 권한이 없는 작업에는 실행 버튼을 제공하지 않습니다.

| 기능 | 기본 Proxmox 권한 | 조건 |
| --- | --- | --- |
| VM·LXC 시작·정상 종료·재부팅·강제 중지 | `VM.PowerMgmt` | 상태에 따라 표시 |
| VM 강제 재시작·일시 중지·재개 | `VM.PowerMgmt` | QEMU 전용, 재개는 일시 중지 상태 |
| 스냅샷 생성·삭제 | `VM.Snapshot` | 지원하는 스토리지 필요 |
| 스냅샷 복원 | `VM.Snapshot` 또는 `VM.Snapshot.Rollback` | 기존 스냅샷 선택 |
| 백업 실행 | `VM.Backup`, 대상의 `Datastore.AllocateSpace` | 같은 노드의 백업 지원 스토리지, snapshot 모드·Zstandard |
| 전체 복제 | `VM.Clone`, 새 ID의 `VM.Allocate`, 대상의 `Datastore.AllocateSpace` | 새 ID·이름·같은 노드의 스토리지 지정 |
| 노드 이동 | `VM.Migrate` | 허용 범위의 다른 온라인 노드, 실행 중인 VM은 온라인 이동·LXC는 재시작 이동 |
| CPU 코어·메모리·자동 시작 변경 | 각각 `VM.Config.CPU`·`VM.Config.Memory`·`VM.Config.Options` | 일부 설정은 종료 후 시작해야 적용 |
| 템플릿 변환·VM/LXC 삭제 | `VM.Allocate` | 중지 상태에서만 제공 |
| 노드 재부팅·종료 | `Sys.PowerMgmt` | 해당 노드가 온라인인 경우 |

총 **20종 작업**을 지원합니다. UI에는 기본 권한과 리소스 상태를 반영합니다. 복제 시 원본 네트워크의 `SDN.Use`, 스토리지의 콘텐츠 종류, HA·잠금·하드웨어 상태 등 입력값과 서버 구성에 따른 추가 조건은 Proxmox가 최종 검증합니다. 따라서 메뉴에 표시된 작업도 구성 변경이나 추가 권한 부족으로 거절될 수 있습니다.

실행 전 2분간 유효한 확인 화면에서 대상 ID를 입력해야 합니다. 확인 요청은 한 번만 사용할 수 있고, 실행 직전에 소유권·설정 버전·리소스 범위·현재 권한·대상 상태를 재검사합니다. 요청 전송 중 연결이 끊어지면 **결과 확인 필요**로 표시하고 자동 재전송하지 않습니다. 재실행 전 Proxmox 작업 목록을 확인하세요.

비동기 작업은 Proxmox UPID로 추적합니다. 패널이 열려 있을 때 진행 중인 작업을 5초 간격으로 확인합니다. 동기 API의 ‘완료’는 API 요청이 성공했다는 의미이며, 노드 종료 등 실제 상태 변화는 다음 상태 갱신에서 확인합니다. 앱에서 실행하지 않은 과거 Proxmox 작업은 이 목록에 포함하지 않습니다.

PVE의 모든 API를 임의로 호출하는 콘솔은 제공하지 않습니다. VM/LXC 신규 설치·백업 복구·디스크/네트워크 편집·ACL/방화벽·Ceph/HA 설정·VNC/SPICE/셸은 Proxmox 원본 화면에서 관리하세요. 이번 연동은 위의 일상 운영 작업과 상태 조회를 지원합니다.

## 갱신·제한·백업

보이는 북마크에 연결된 서버와 열려 있는 상세 패널만 갱신합니다. 북마크마다 별도로 호출하지 않고 연결별 DB 캐시와 조회 임대를 사용해 여러 탭·프로세스의 호출을 합칩니다. 기본 60초, 최소 30초 간격이며 수동 새로고침에도 같은 예산을 적용합니다. 오류가 발생하면 마지막 정상 데이터를 유지하고 제어 버튼을 숨깁니다. 패널이 닫히면 작업 추적 폴링도 종료합니다.

계정당 8개·서버 전체 64개 연결, 연결당 100개 북마크, 리소스 응답 2MB·20,000개, 동시에 최대 4개 인벤토리 조회로 제한합니다. 리소스 상세·작업 확인은 연결당 초당 1회, 제어는 사용자당 분당 10회이며 요청은 자동으로 재시도하지 않습니다. 비밀정보나 원본 오류 응답을 브라우저·로그에 전달하지 않습니다.

일반 JSON 북마크 백업에는 이 연결의 토큰과 제어 설정을 포함하지 않습니다. 복원한 북마크는 연결 설정에서 다시 선택하세요. 연결 설정·작업 내역을 함께 보존하려면 PostgreSQL 전체 백업과 기존 `AUTH_ENCRYPTION_KEY`를 보관합니다. 연결 삭제는 앱 설정·작업 내역만 지우며 Proxmox 서버의 리소스나 실행 중인 작업을 취소하지 않습니다.

API·권한 규격은 [Proxmox API 안내](https://pve.proxmox.com/wiki/Proxmox_VE_API), [유효 토큰 권한 조회 구현](https://github.com/proxmox/pve-access-control/blob/master/src/PVE/API2/AccessControl.pm), [QEMU API](https://github.com/proxmox/qemu-server/blob/master/src/PVE/API2/Qemu.pm), [LXC API](https://github.com/proxmox/pve-container/blob/master/src/PVE/API2/LXC.pm)를 기준으로 합니다.
